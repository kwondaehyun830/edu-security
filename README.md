# 7주차 보안 실습 과제 정리

## /page (인덱스)

- **기능**
    - 각 버튼 클릭 시 해당 페이지로 이동 (Login, Memo, 과제3)
    - 버튼에 커서 올리면 배경색이 검정, 클릭하면 흰색으로 돌아오는 효과(css)
- **구현**
    - html, css로 이동/스타일 구현

---

## Login Page

- **기능**
    - 아이디: text 입력, 비밀번호: password 입력(가림 처리)
    - 하단 login 버튼 클릭시 로그인(서버와 연동)
    - 버튼에 커서 올리면 배경 흰색, 클릭시 파란색으로 복귀
- **login.js**
    - 로그인 폼 기본 제출 막음(비동기 처리)
    - 비밀번호 sha256 해싱 후(대소문자 맞춤) 서버 전송
    - 서버 응답 메시지에 따라 성공/실패 alert
    - 로그인 성공시 JWT 토큰 발급/저장(localStorage)

---

## Memo Page

- **기능**
    - 인덱스 페이지에서 Memo 버튼 클릭 시 /memo 이동
    - 메모 입력 후 작성 버튼 클릭 시 하단에 실시간 출력
    - 전체 삭제 버튼으로 메모 모두 삭제
    - fetch API로 /api/memo (POST, GET), /api/memo/delete (POST) 연동
    - 작성/삭제 버튼 호버/클릭 시 스타일 변화(css)

---

## 상단 인사/로그아웃

- 모든 페이지 우측 상단에 `{id}님 안녕하세요.` 표시
- JWT 토큰이 있으면 /api/me로 id 조회, div에 표시
- 로그아웃 버튼 클릭 시 localStorage의 JWT 제거 + 새로고침

## 보안 구현/설명

### XSS

- **방어 방법:**  
  - 클라이언트에서 메모 출력 시 `innerText` 사용  
  - `<script>`, `<img onerror>` 등 입력해도 "글자"로만 표시, 실행 불가
- **직접 테스트:**  
  - `<img src=x onerror="alert('XSS')">` 입력 → 화면에 텍스트만, alert 없음

### CSRㄹ

- **방어/원리:**  
  - POST 요청은 모두 fetch API(자바스크립트)로만 처리  
  - 서버는 JWT 토큰 인증만 허용, 외부 폼/이미지 등에서는 요청 불가
  - 실제 로그인/세션/쿠키 기반 인증이 없어 CSRF 위험 낮음
- **실제 보안:**  
  - JWT가 있지 않으면 주요 요청 거부(401/403 등)
  - JWT 인증 구조 자체가 CSRF에 매우 강함
